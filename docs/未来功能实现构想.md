## 三、高优先级功能详解

### F-01：多角色对话模式 🔴

**功能描述**：同时与同一书籍的多个角色对话，角色间可相互引用，用户可主持辩论或群聊。

**技术路径**：

```
1. 扩展 ChatSession 模型
   ChatSession {
     personaIds: string[]  // 从 single personaId 扩展
     mode: 'single' | 'group'
   }

2. 新增群聊 UI 模式
   src/features/chat/components/GroupChatView.tsx
   - 消息按角色分组显示
   - 角色头像在消息旁

3. 修改 LLM 调用
   - system prompt 包含所有选中角色的设定
   - 消息格式：[PERSONA_A]: 内容
   - RAG 查询聚合所有角色的上下文

4. 修改 Persona Generator
   - 生成时包含角色间关系描述
   - "A 和 B 是母女关系，经常因观念不同而争论"
```

**影响文件**：

- `src/shared/types/index.ts` — ChatSession 类型
- `src/features/chat/ChatInterface.tsx` — UI 改造
- `src/features/chat/services/chat-service.ts` — LLM 调用改造
- `src/shared/store/index.ts` — Zustand 扩展

**工期估算**：中（2-3 周）

---

### F-02：语义导航 🔴

**功能描述**：自然语言查询导航书籍内容，如"找出罗密欧初遇朱丽叶的场景"直接跳转到对应段落。

**技术路径**：

```
1. 阅读器内嵌搜索栏
   src/features/reader/components/SemanticSearchBar.tsx
   - 接受自然语言查询
   - 显示搜索结果列表

2. 复用现有 RAG 搜索
   - ragSearch(query) → 返回匹配段落
   - 每个结果含 paragraphIndex 和 offset

3. 跳转机制
   - 复用现有的 pendingCitation 机制
   - pendingCitation = { bookId, paragraphIndex, offset }
   - 阅读器监听并滚动到目标位置

4. 可选：场景类型标注
   - 在 chunking 时 LLM 标注类型：[战斗]、[对话]、[独白]
   - 搜索可按场景类型过滤
```

**影响文件**：

- `src/features/reader/ReaderPage.tsx` — 新增搜索栏
- `src/features/reader/components/SemanticSearchBar.tsx` — 新组件
- `electron/main/rag-handler.ts` — 新增场景标注逻辑

**工期估算**：小（1 周）

### F-03：对话记忆与长期上下文 🔴

**功能描述**：聊天记住与角色历次对话内容，下次访问时问"上次我们讨论的他的动机是什么"可引用历史。

**技术路径**：

```
1. 持久化 ChatSession 历史
   - IndexedDB 存储所有历史会话（超越当前 session）
   - 每个 Persona 的对话历史关联

2. LLM 对话压缩
   - 当历史过长时，LLM 生成摘要
   - persona.summary 字段存储关键讨论点

3. 检索历史上下文
   - buildConversationHistoryPrompt(personaId)
   - 从 IndexedDB 取出相关历史
   - LLM 压缩后注入 system prompt

4. 新增 IPC 通道
   - rag:get-conversation-history
   - rag:summarize-conversation
```

**影响文件**：

- `src/shared/store/index.ts` — 新增历史存储逻辑
- `src/features/chat/services/conversation-history.ts` — 新服务
- `electron/main/ipc-handlers.ts` — 新通道
- `electron/main/rag-handler.ts` — 新增历史检索

**工期估算**：中（2 周）

### F-04：书签与批注系统 🔴

**功能描述**：阅读时高亮段落、添加个人批注，批注内容在讨论对应角色时自动注入上下文。

**技术路径**：

```
1. 新数据类型
   interface Highlight {
     id: string
     bookId: string
     paragraphIndex: number
     offsetStart: number
     offsetEnd: number
     text: string
     annotation?: string  // 用户批注
     createdAt: number
     tags?: string[]
   }

2. 存储层
   - IndexedDB 存储 Highlight
   - 与 RAG Cache 分开，独立索引

3. 阅读器内嵌高亮 UI
   - TextViewer 支持选中文本
   - 弹出高亮/批注按钮
   - 高亮显示（不同颜色分类）

4. 批注上下文注入
   - 聊天时检测当前 paragraphIndex
   - 如有高亮/批注，附加到 RAG 上下文
   - 用户可见批注引用标记
```

**影响文件**：

- `src/shared/types/index.ts` — Highlight 类型
- `src/features/reader/components/TextViewer.tsx` — 高亮选区
- `src/features/reader/components/HighlightPopup.tsx` — 新组件
- `src/features/chat/services/rag-context-builder.ts` — 注入批注

**工期估算**：中（2 周）

### F-05：EPUB/PDF 结构解析 🔴

**功能描述**：解析 EPUB 和 PDF 的章节结构、脚注、图片引用，实现"章节感知"RAG。

**技术路径**：

```
1. 新增解析器
   src/lib/epub-parser.ts     // 基于 epub.js
   src/lib/pdf-parser.ts      // 基于 pdf.js

2. 章节类型
   interface Chapter {
     title: string
     cfi?: string        // EPUB CFI
     pageNum?: number    // PDF 页码
     startParagraph: number
     endParagraph: number
   }

3. 书籍元数据扩展
   interface Book {
     // ... 现有字段
     chapters?: Chapter[]
     hasImages: boolean
     footnotes?: Footnote[]
   }

4. RAG Chunking 改造
   - 按章节边界分割（保留章节信息）
   - chunk.metadata.chapterTitle
   - 搜索可限定章节范围

5. 阅读器章节导航
   - 左侧/顶部章节下拉框
   - 章节进度指示
```

**影响文件**：

- `src/lib/epub-parser.ts` — 新文件
- `src/lib/pdf-parser.ts` — 新文件
- `electron/main/rag-handler.ts` — 重构 chunking
- `src/features/reader/ReaderPage.tsx` — 章节导航 UI
- `src/shared/types/index.ts` — Book 类型扩展

**工期估算**：大（3-4 周）

## 四、中优先级功能详解

### F-06：夸书籍角色迁移 🟡

**功能描述**：将一本书的角色（如福尔摩斯）迁移到另一本书的讨论中。

**技术路径**：

- 存储角色 Persona 时同时存储其 representative embedding
- 跨书籍激活时，用 embedding 相似度在当前书中找相关段落
- 回退：通用"博学学者"人格，可讨论任何书

---

### F-07：书签俱乐部会话导出 🟡

**功能描述**：导出会话为 `.immersai-session` 格式，可分享给其他人导入重放。

**技术路径**：

- 新格式：`{ version, messages, personas, citations }` 压缩 JSON
- 不含 system prompt（导入时重新生成）
- 校验 book content hash，匹配时重建 RAG 上下文

---

### F-08：阅读数据洞察 🟡

**功能描述**：仪表盘展示阅读统计：章节进度、讨论最多的角色、阅读速度、争论最多的段落。

**技术路径**：

- Zustand Store 新增追踪字段
- 新增 `InsightsPage.tsx`
- LLM 定期生成"阅读摘要"

---

### F-09：馆长 Agent 查询模式 🟡

**功能描述**：扩展馆长 Agent 能力，回答"我的书房有多少本书？""哪位作者出现最多？"等关于书房本身的问题。

**技术路径**：

- 新增 `query_library` 意图识别
- 从 Zustand Store 聚合书籍元数据
- LLM 生成自然语言回答

---

### F-10：角色语音模式 (TTS) 🟡

**功能描述**：角色用语音朗读回复，配合性格/时代设定语音特征。

**技术路径**：

- Persona 类型新增 `voiceConfig` 字段
- Web Speech API (`SpeechSynthesis`) 输出语音
- LLM 生成时附带 `voice_hint`（"带有维多利亚时代正式语调"）

## 七、总结

**短期（1-2 月）**：完成 F-01、F-02、F-03、F-04，充分利用现有 RAG 和 Chat 基础设施。

**中期（3-4 月）**：F-05 EPUB/PDF 解析是较大工程，回报也最高，实现书籍结构感知后所有功能受益。

**长期**：F-10 TTS、F-12 氛围阅读等属于体验增强型功能，可在下阶段考虑。

所有功能均基于现有架构能力向外延伸，无需引入新的技术框架。
